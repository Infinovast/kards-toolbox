# 项目架构

## 技术与运行边界

React 19、TypeScript、Vite 和 Tailwind CSS 4 构成界面。Wails v2 通过系统 WebView2 显示界面，Go 提供 Windows 桌面能力。卡组和设置通过 localforage 保存在 IndexedDB，桌面牌库快照独立保存在 JSON 文件中。桌面与浏览器共用 Canvas 生图逻辑。

界面经 `src/lib/wailsDesktop.ts` 调用 Go。Wails 的本地资源入口提供 EXE 内嵌的界面和静态图包，以及数据目录中的卡图包。独立 Web 服务可用于浏览器开发。

```text
React 界面 → 共享业务模块 → localforage / IndexedDB
                  ↓
             Wails 桌面接口
                  ↓
Go 桌面层 → 固定数据源、图片下载、文件对话框、剪贴板
```

## 卡牌数据更新

设置中选择 `kardsplayer` 或 `kardscom` 来源，调用共享分页与校验逻辑。桌面由 Go 请求对应的固定 GraphQL 端点，浏览器使用同样的数据模型。

```text
手动获取 → 分页及完整性校验 → 候选快照 → 新旧差异 → 用户应用
                                              ↓
                                      当前快照 / 上次快照
```

完整获取后按 `importId` 比较新增、修改和移除，多语言文本逐字段比较。获取、应用和回退先完成持久化，再切换内存数据；取消、网络错误或写入失败不会覆盖当前牌库。任务位于模块级状态中，切换页面不终止获取。

图片地址属于卡牌数据；获取牌库不下载图片，应用数据也不清理现有图片缓存。卡名相同的原卡、老兵卡等记录按各自标识独立保存。完整牌库校验时按 `VeteranOf` 关联将老兵卡的 `Special` 扩展包替换为本体扩展包，覆盖随包数据、已存快照及后续获取；衍生判断独立检查老兵关联，避免扩展包归一化后进入构筑卡池。

本地天气清单补齐变体和生成关系；18 张 `temp_` 变体的 `importId` 归一化为空字符串、移除 `json.import_id`，不分配本地卡组码 ID，也不进入卡组码索引。列表、批量下载、缓存统计与无 ID 数据差异使用 `cardId` 区分，最近缓存批次新增 `cardIds` 并兼容旧 `importIds`。基础天气卡保留来源数据及图片地址；加载旧快照时修复曾被补充数据覆盖的基础天气图片地址。

## 图片缓存与后台下载

卡图统一使用中文完整图和缩略图，多语言卡牌文字仍用于搜索和详情。每种图片以卡牌编号及实际 URL 组成独立缓存键，URL 改变后可下载新文件，旧缓存保留以支持数据回退。

- 查看或批量缓存一张卡时，同时补齐完整图与缩略图；失败重试只下载缺项。
- 卡牌条读取独立缩略图，悬浮大图及生图读取完整图；不以整图裁切冒充缩略图。
- 天气变体跟随原体的最新缩略图地址，共用原体缩略图缓存与并发下载；完整卡图仍各自保存。更新或载入牌库时自动修正旧变体缩略图地址。
- 桌面下载由主进程校验 URL 和文件签名；浏览器预览通过图片代理获取。
- 后台队列默认间隔 500ms、并发 1，可调整为 100ms–30s、1–8 个任务。连续失败延长启动间隔，等待计入速度和剩余时间。
- 暂停不取消已发出的请求，恢复后继续未完成项；用户主动暂停的时间不计入平均速度。
- 缓存页只枚举与读取本地图片。按当前牌库分别计算完整图和缩略图的卡牌覆盖数，支持成对删除、失败重试及旧缓存清理。

| 数据 | 存储键或位置 | 用户备份 |
| --- | --- | --- |

| 卡组与收藏夹 | `kards_decks`、`kards_collections` | 包含 |
| 构筑草稿 | `kards_builder_draft` | 包含 |
| 开包累计历史 | `kards_pack_history_v1` | 包含 |
| 设置、分类与用户图片 | `kards_settings` 等用户存储键 | 包含 |
| 桌面完整图与缩略图 | 由桌面缓存接口管理 | 不包含 |
| 浏览器完整图与缩略图 | IndexedDB 的 `kards_card_image_v2_` 前缀 | 不包含 |
| 下载失败与最近批次 | `kards_card_image_failures_v1`、`kards_card_image_batch_v1` | 不包含 |
| 卡组生图缓存 | `deck_img_local_v1_` 前缀 | 包含 |
| 迷你分享图缓存 | `deck_img_mini_v1_` 前缀 | 包含 |

用户数据目录为 `%APPDATA%\kards-toolbox`，可通过环境变量 `KARDS_USER_DATA_DIR` 指定隔离目录。WebView2 的 IndexedDB 位于其中的 `webview2/` 子目录；即使沿用同一数据根目录，也不会自动读取或迁移 Electron 的 IndexedDB。卡组和设置需先在原版应用中导出用户备份，再在新版应用中导入。用户备份只包括卡组、设置和其他在表中标注的用户数据。现有 `packs/cards.kpak` 可直接复用，兼容卡图包也可作为 `cards.kpak` 放到 EXE 旁边，在新数据目录中导入。

用户数据初始化先完整读取、校验并创建启动快照，再开放自动保存；任一项读取失败时保留原值并显示恢复入口。卡组、设置、草稿和开包历史的写入经共享队列串行执行；自动保存失败保留待重试值并显示全局提示，构筑的显式保存等待实际写入成功后才退出。备份导出等待队列，存在未保存修改时拒绝导出过期数据。

`kards_user_auto_backups_v1` 保留最多 3 份不同用户快照，记录启动或恢复前的数据，不包含可重建的卡组图片；设置可选时间点恢复。导入先校验全部键和值，再保存原值至 `kards_user_restore_journal_v1` 后逐项替换。任何写入失败都会按日志回滚；回滚未完成时阻止其他自动写入，下一次初始化优先恢复原数据。自动快照及恢复日志不递归进入用户导出文件。

## 构筑、资源与界面

欢迎页显示偏好保存在 `kards_settings.showWelcomePage`，默认为 `true`。启动读取并合并设置后选择欢迎页或卡组页，旧设置与旧备份未包含该字段时沿用默认值。左上角 Logo 始终提供欢迎页入口，构筑中仍通过现有离开确认处理未保存修改。欢迎页的导入与战备入口复用现有弹窗，成功添加后进入卡组页；搜索入口在牌库加载后聚焦搜索框。

卡组详情通过带递增 revision 的选择请求向对比页传入当前卡组，左侧复用现有卡组选择与自动分析，右侧打开现有卡组菜单；普通导航不重复应用请求。双卡组对比保留两个独立输入与校验状态，可粘贴卡组码、分享文本或从 App 传入的现有卡组中选择；选择时保留名称、总部和卡背信息，直接使用所选记录分析，避免读取到尚未更新的输入状态。所选记录保持期间禁用两个分析按钮，编辑输入时解除。“仅分析”只更新本次分析；“导入并分析”另经 App 保存到卡组列表，分析结果相同。有效输入解析为卡牌数量映射，复用 `summarizeDeckCosts`、`analyzeDeckAbilities` 和 `DeckCostChart` 的费用柱状图，两侧按共同最大值缩放。两列使用 CSS subgrid 共享输入区行高，避免 textarea 扩展导致分析区错位。分类、平均费、单位/指令比及稀有度合并到固定宽度对比表，按字段比较加粗较大数量或较小平均费，加粗项和差距使用同一侧主题色；单位/指令比不计算差距。能力评分继续使用既有中性场景与典型区间，合并为左红圆点、右蓝三角的五行点图，分数跟随标记，右侧增加较大一方配色的绝对差距胶囊。图例读取实际卡组名并显示典型区间色块。无效卡组码、卡牌缺失和不完整卡组保留状态反馈。

对比页通过欢迎页、侧栏和卡组页顶栏的共享打开动作进入。App 在首次进入后保留挂载，以可见性切换保留本次运行中的输入、校验与选择锁定状态、分析结果、生成图片和内部滚动位置；`active` 控制 Esc 监听，隐藏时不会干扰其他页面。现有卡组列表由 App 传入主盟国和复用的 `reservedDeckIds` 标记，列表左右分别显示名称及预备标记、无后缀彩色国家图标。统计表使用绝对差距，评分每行的名称与本行差距胶囊共用较高分一侧的颜色，同分为中性色。

对比页卡组名称下的完整大图调用共享 `renderDeckImage`，沿用当前卡组的总部和卡背信息，加载与生成失败在对应位置反馈；点击图片通过 Portal 放大，复用现有模态键盘及焦点恢复机制。卡组码 textarea 初始与名称输入框同高，内容变化和窗口变化时按实际内容高度调整。

卡组码使用共享编解码模块；总部由显示层补入总数，不占用可用牌记录。规则校验与卡池筛选分开：主国和盟国卡池限制决定候选，规则决定提示；已有或未知卡不因筛选被删除。
缺省卡组名称由 `defaultDeckName` 统一生成，使用主盟国的中文首字（同国不重复），覆盖导入、对比、空白构筑和生图；自定义或分享文本名称优先保留。
卡组导入通过 `deckCardSignature` 将卡牌数量映射按 import ID 排序后序列化，以 `findDuplicateDeck` 在现有列表查重，忽略国家头、总部、名称、卡背及牌序。普通导入、剪贴板/图片确认与战备卡组共用入口；对比导入还在串行 `updateUserData` 回调中检查最新保存列表，防止两侧同时导入同一卡组。重复导入不覆盖已有记录，对比页继续分析并提示现有名称。

卡池按可见宽高在预设尺寸范围内选择完整行列，不纵向滚动；容器变化时重新计算，滚轮驱动分页；末页不向前补齐。资料库与构筑共用文字、类型、子类、费用等筛选语义；文字中的“.”匹配任意单个 Unicode 字符，其余正则符号转义后按字面匹配；中文本地化卡名另做去空白、标点和符号的匹配，描述及其他语言不参与这种归一化。`x` 加三/四位数字进入单位数值搜索模式，分别匹配部署/攻击/防御或部署/行动/攻击/防御，各指定数值需为 0–9 整数；与现有筛选组合。搜索表达式只在查询改变时重新编译。牌库纯 3/4 位数字且普通查询结果不超过 3 张时，额外以清空筛选的 `x` 查询计算属性数值候选，存在结果才显示可点击入口，点击后应用对应查询。子类图标由 `assets.json` 的 `subclasses` 映射统一管理；词条按“或/与/非”匹配（默认或；左键前进、右键后退；非为选中项均不命中），`keywordCount` 以 0 表示不限、1–3 精确匹配 `cardKeywordItems` 的显示数量；数量条件与其他条件共同生效，并隐藏总部堆叠；`selectCardFilterKeywords` 处理无词条与对战/独立词条的互斥选择，资料库带筛选搜索且结果不超过 3 张时，分别计算只保留文字、只保留筛选的结果数量，有结果才提供对应入口，由用户点击后应用；子类映射与官方卡牌数据分开维护。`CardLibrarySettings.tsx` 将文字语言和详情样式收进齿轮按钮的 portal 面板，嵌套选择器沿用 `CustomSelect`；关闭面板恢复焦点，外部点击及焦点离开时收起。纯图标选择菜单采用紧凑宽度与选项尺寸，稀有度原色图标在菜单中放大并保留比例。

牌库主排序相同时，依次按费用、类型（步兵、炮兵、坦克、轰炸机、战斗机、指令、反制指令）升序排列，最后保留原数据顺序。末级排序以天气原体的位置作为该组位置，并按原体、变体 1、变体 2 排列；不修改其费用、类型或战斗属性。筛选隐藏原体时仍保持变体顺序。

资料库详情模式保存在 `kards_settings.cardDetailMode`，支持共享 modal 与原有侧栏。构筑单击立即打开详情，弹窗捕获原点击位置的第二次点击以完成双击加牌，不再为区分单击与双击延迟开窗。卡组详情对卡组按钮的点击单独处理，重复选择当前卡组不触发关闭重开。

卡背、总部及桌布由 JSON 清单管理适用国家、名称、图片及关联关系。选中卡组可临时切换总部桌布，退出后恢复用户设置；生图中的桌布选择仅影响本次导出。生图读取本地缓存，缺图显示占位，不依赖在线出图服务。

资源路径集中维护于 `src/data/assets.json`（阵营、类型、稀有度、扩展包、预备标志、品牌图标、万能卡、卡包）及 `cardbacks.json`、`headquarters.json`、`tablecloths.json`，界面与生图共用清单。`assetCatalog.ts` 负责按用途选择图标：筛选和计数器使用阵营白色图标；战斗机、轰炸机的详情及卡牌条使用空军图标，缺失时回退普通图标；其余使用普通图标。reserved/reversed 阵营变体不加入清单。万能卡按通用及五主国、稀有度登记，战备卡组只使用通用组；卡包记录文件、显示名称、来源分类、国家列表或扩展包 ID，以及标准/军官规格，选包界面与卡池计算共用清单。

桌布清单维护默认项、显示名称、可选的简短 `description`、壁纸国家和总部关联；壁纸国家用于分类，不限制用户选择。`TableclothChoice.tsx` 在悬停或聚焦时以 portal 显示描述气泡，根据视口空间选择上下位置，正文完整显示且不滚动；总部桌布按总部关联标识匹配，直接复用总部清单中的简介字段，其余桌布读取清单描述，缺少文本时省略气泡。壁纸通过 cardId 关联卡牌中文名，通用步兵画面使用已有类型名；已改名的卡背、默认桌布和壁纸保留旧地址映射，已删除的桌布回退到木纹默认项。

总部名称、英文名、简介与历史集中维护在 `src/data/headquarters.json`。清单的 `id` 和 `groupId` 保持稳定，以兼容已保存卡组及专属桌布关联。

界面的颜色、间距、浮层与动画遵循现有界面规范。前端依赖由 npm 管理，桌面依赖由 Go 模块管理。构建时将生产依赖许可和项目声明嵌入桌面 EXE，并随文件夹版另附可读副本。[界面规范](../DESIGN.md) · [第三方说明](../THIRD_PARTY_NOTICES.md)

词条唯一清单位于 `src/data/cardKeywords.json`：`order` 是可选整数显示序号，同值保留原顺序，未配置时不出现在详情词条栏，也不计入数量筛选；`cardKeywordItems` 仅对详情属性栏按该值升序排序（数值越小越靠前），仅显示已配置 `order` 的词条，保留同值项的原始相对顺序，不修改原卡属性数组，也不改变词条筛选菜单顺序。`label` / `english` 管理中英对照，`icon` 指向可选词条图标（动员使用 `mobilize.png`，老兵使用 `veteran.png`）；PNG 保留真实透明空白与抗锯齿边缘，避免半透明底层形成灰色矩形，`attribute` 标识属性词条，`highlighted` 标识战斗词条；战斗词条属于属性词条，属性词条属于完整词条表。`numbered` 声明重甲/情报的数值后缀，`attributeAliases` 管理属性别名及详情可见性，`excludeFollowing` 避免“战斗”命中“战斗机”。`filterGroup` 管理对战、独立、扩展、特殊四列筛选分类及排列顺序；特殊词条在规则文字中匹配中英文标签，并保留英文单词边界及排除后缀规则；“控制”仅匹配描述中含“控制 1 个”的卡牌，`descriptionPrefix` 匹配并加粗描述中的“词条：”形式（冒号包含在内），`textAliases` 补充 `Show when drawn` 等英文描述前缀，`cardIds` 维护倒计时卡名单，`textMatch: false` 排除纯筛选项目的正文匹配。筛选菜单、详情属性与中英文规则文字加粗均由该清单派生；战斗强调色只用于筛选项与详情的词条信息，规则正文仅加粗。

卡组生图快捷页在进入和窗口重新获得焦点时读取剪贴板；同一次页面会话中，相同剪贴板卡组码不会重复覆盖手动输入。有效输入停止 350ms 后并行生成完整图与迷你图，过期请求不会替换新预览。更换桌布通过回调复用 App 的生图桌布选择窗及上传裁剪流程，快捷页保留本次背景覆盖值，优先于总部默认桌布，选择后重绘两种图片，不更改应用桌布；关闭选择窗时清理回调。图片放大通过 Portal 复用详情遮罩和模态键盘处理；历史侧栏沿用卡组详情浮栏布局，只枚举完整图缓存键，可见记录读取图片后缩为小图，旧缓存缺少迷你图时补生成。完整图重绘会先清除旧迷你缓存，迷你图写入等待完整图保存成功，避免标题、总部或桌布更新后配对错误。该页面不创建卡组。

完整生图由 `summarizeDeckCosts` 计算含实际张数、不含总部的费用和类别统计，随 `DeckRenderRequest.statistics` 传给桌面；两种渲染器共用 `deckStatisticsSvg`，饼图颜色与卡组分析都读取 `DECK_COST_CATEGORIES`。背景在合成清晰卡牌与数据前单独模糊和压暗。

## 模拟开包

`assets.json.cardpacks` 登记 14 种来源、每种 2 种规格，共 28 张资源图。国家包按 `nations` 匹配（盟国包为五盟国合集），扩展包按 `set` 匹配；排除衍生、老兵及无标准稀有度记录，允许一包内重复卡。

`PACK_RULES` 按普通/限定/特殊/精英记录单卡基础概率：标准包 74.6/19.9/4/1.5，军官包 50.6/32.1/12.4/4.9。`PackReward` 区分实际卡牌与通用万能牌，避免将模拟万能牌写入真实牌库。军官包的每个可用稀有度桶增加一份通用万能牌，与桶内每张卡牌占据相同抽取区间；标准包不增加万能牌。抽取后，标准包补足至少 1 张限定或以上，军官包补足至少 2 张限定或以上和至少 1 张特殊或以上，保底候选沿用相同的卡牌/万能牌结果池；始终保留 5/7 张。缺失稀有度时只在可用稀有度间归一化，无法满足保底时停止并提示更新数据。

翻卡由原生 Web Animations API 控制，依次抬升、翻转、落下，稀有度决定持续时间和局部冲击反馈；退回、离页和重新开包会清理旧动画。缩减动态效果模式保留短促状态切换。单包明细仅保存在当前会话；累计标准/军官次数及各稀有度张数保存在 `kards_pack_history_v1`，在一次成功开包时写入，写入成功后才展示结果，翻牌和返回不重复计数。按 100/330 计算模拟花费；顶栏复用迷你分享图的通用万能牌小图统计，包含真正抽到的万能牌。万能牌使用通用卡背及本地 Common 资源，不调用真实卡图下载或牌库详情接口；完整卡牌图沿用共享缓存及配套缩略图下载。
